# Architecture Decision Records

Major UMBRAL decisions are documented as Architecture Decision Records (ADRs)
to preserve their reasoning, context, and consequences over the life of the
project.

Create an ADR when a decision establishes or materially changes a durable
technical, architectural, operational, or governance direction. ADRs are
appropriate for choices that affect system boundaries, data ownership,
interfaces, hosting or service strategy, security posture, development
workflow, or long-term project constraints. Do not create an ADR for routine
implementation details or unapproved design decisions.

Use [ADR_TEMPLATE.md](ADR_TEMPLATE.md) for new records. Give each record the
next available `ADR-XXX` identifier and retain superseded records so the
project's decision history remains understandable.

[DECISIONS.md](../../DECISIONS.md) remains the repository-level decision log
for concise technical, process, and repository decisions. Use an ADR when a
decision needs durable context, alternatives, and consequences; link the
related `DECISIONS.md` entry and ADR when both are useful.
