# Technical Planning

Engine-specific and implementation-specific technical planning.

This directory is distinct from [architecture/](../architecture/README.md),
which is intentionally technology-neutral and records approved system
boundaries. Documents here are concrete, scoped to a named deliverable, and may
be superseded or deleted when that deliverable is complete.

## Documents

- [Prototype Architecture](PROTOTYPE_ARCHITECTURE.md) — technical plan for Feel
  Prototype 01: the smallest build capable of testing whether UMBRAL is
  enjoyable to control and interact with.
- [Implementation Plan](IMPLEMENTATION_PLAN.md) — phases, playtest protocol,
  kill criteria, and the one-week scope for that prototype.

## Boundary

Documents in this directory make no design decisions. Where a technical plan
requires a decision reserved by the
[First-Hour Design Framework](../design/experience/FIRST_HOUR.md) or the
[Game Design Document](../design/GAME_DESIGN_DOCUMENT.md), it must name a
neutral placeholder and record the open decision it stands in for. See
[PROTOTYPE_ARCHITECTURE §2](PROTOTYPE_ARCHITECTURE.md#2-design-inputs-required).
